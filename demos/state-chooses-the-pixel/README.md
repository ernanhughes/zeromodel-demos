# State Chooses the Pixel

The introductory ZeroModel Web demonstration.

A browser state selects one cell in a lossless policy image. The colour sampled from that image decodes to an action. The runtime contains no Python, model, prompt, API call, or inference server.

## Demonstration staircase

This is step one of the public ZeroModel Web sequence:

1. **State Chooses the Pixel** — state addresses an image and reads an action.
2. **Edit the Intelligence** — change the image and change behaviour.
3. **Transition Evidence** — inspect before/after state and declared contracts.
4. **Representation Matters** — show how a poor representation erases evidence.
5. **Compile the Representation** — generate an evidence-preserving policy artifact.
6. **Fight the Image** — a shooter enemy controlled by a policy image.

Each step adds one idea while retaining the same browser-native foundation.

## What this version proves

Within this bounded 4×4 policy:

```text
threat + energy
    ↓
grid address
    ↓
image coordinate
    ↓
colour sample
    ↓
decoded action
```

The JavaScript is the reader and actuator. `policy.svg` contains the decision table.

## Run locally

Serve the directory over HTTP so that `fetch()` and canvas pixel access operate normally:

```bash
cd demos/state-chooses-the-pixel
python -m http.server 8080
```

Then open:

```text
http://localhost:8080
```

Python is used only here as a convenient static file server. It is not part of the demo runtime. Any static server works.

## Hugo deployment

Copy this directory into the Hugo website's static tree:

```text
zeromodel.org/static/demos/state-chooses-the-pixel/
```

Then embed it from a Hugo page with an iframe:

```html
<iframe
  src="/demos/state-chooses-the-pixel/"
  title="State Chooses the Pixel — ZeroModel Web demo"
  loading="lazy"
  style="width:100%;min-height:1100px;border:0"
></iframe>
```

An iframe is the safest first integration because the demo remains independently runnable and cannot conflict with the Hugo theme. A later shared web component can replace it when several demos prove the same integration needs.

## Files

- `policy.svg` — lossless executable visual policy.
- `policy.json` — dimensions, geometry, colour decoder, and bounded claim.
- `demo.js` — generic browser reader for this manifest shape.
- `index.html` and `demo.css` — static presentation.

## Extension exercise

Change one rectangle colour in `policy.svg`, reload the page, and evaluate the same state again. The reader code remains unchanged but the decoded action changes.

That is the central idea:

> Replace the image and you replace the policy.

## Limitations

This introductory image is hand-authored to explain the execution mechanism. It is not yet generated by the ZeroModel compiler, and it does not establish learning, open-world perception, autonomous semantic discovery, or general intelligence.
