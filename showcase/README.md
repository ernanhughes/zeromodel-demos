# Showcase

Showcases are polished ZeroModel experiences intended for the product website, public presentations, launch material, and commercial evaluation.

A showcase is not merely an attractive experiment. It should be built from a demonstrated capability, use bounded claims, and make the value understandable without requiring the visitor to read the core repository first.

## Admission criteria

A showcase belongs here when:

- the underlying capability has already been reproduced as a demo, lab, or core benchmark;
- the interaction and visual presentation are intentionally designed;
- the supported claim and limitations are visible in the experience;
- it can be deployed independently or embedded by `zeromodel.org`;
- its ZeroModel release dependency is pinned;
- it has a stable public route and representative screenshots.

## Presentation principle

A showcase should make three things visible:

1. what state or evidence entered the system;
2. what representation or address was selected;
3. why the deterministic result followed.

The visitor should leave understanding that ZeroModel is compiled, inspectable visual intelligence rather than a runtime generative model.
